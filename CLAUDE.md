# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A Godot 3rd-person endless-runner-style adventure game ("Zelda-like Educational Game"). The player walks an infinite procedurally generated field, switches between several characters, and is chased by hostile NPC crocodiles. The codebase is written to be read — scripts are heavily commented for teaching purposes, so match that density when editing existing files.

**Engine version:** The actual target is **Godot 4.5** (`project.godot` declares `config/features=("4.5", ...)` and CI uses `barichello/godot-ci:4.5`). README.md and QUICKSTART.md say 4.3 — they are stale; trust 4.5.

## Commands

There is **no test suite, linter, or build script** — this is a pure Godot project driven from the editor and CI.

```bash
# Run the game from the CLI (main scene)
godot --path . scenes/main.tscn

# Run a single scene in isolation (e.g. test one character or the player)
godot --path . scenes/characters/primm.tscn

# Headless web export — same command CI runs (requires the "Web" export preset + templates)
mkdir -p build/web && godot --headless --export-release "Web" build/web/index.html

# Serve a local web build for testing (WebAssembly needs an HTTP server, not file://)
./serve.sh        # Linux/macOS
```

Editing is expected to happen in the Godot editor (`godot project.godot`); the editor reimports assets into the gitignored `.godot/` cache. Each `.gd` has a sibling `.gd.uid` — Godot manages these; don't hand-edit them. (Note: `scripts/windman_whole_body_animator.gd.uid` is orphaned — its `.gd` no longer exists.)

3D character/enemy models are **generated by Python**, not modeled by hand. Regenerate via `python3 scripts/generate_*.py` (depends on `trimesh` + `numpy`; `generate_windman_separate.py` also needs `shapely` + `scipy` for the extruded chest "W"); output goes to `assets/models/characters/`. The live Windman is the 11 separate parts in `windman_parts/` (regenerated by `generate_windman_separate.py`), assembled and animated by `scenes/characters/windman_updated.tscn` — **not** the monolithic `windman.glb` (used only by the orphan `windman_3d.tscn`).

## Architecture

### Node discovery is group-based, not reference-based
Systems never hold hard references to each other. The player adds itself to the `"player"` group; terrain and enemies locate it with `get_tree().get_first_node_in_group("player")` / `get_nodes_in_group(...)`. When adding a system that needs the player (or enemies), use groups rather than `$`-paths or exported references. Relevant groups: `player`, `crocodile`, `enemy` (used by `piglet_crocodile_ai.gd`), and `enemies` (used by `enemy_controller.gd` — note the inconsistent pluralization between the two enemy scripts).

### Everything in the world is spawned procedurally from the terrain
`scripts/endless_terrain.gd` (on the `EndlessTerrain` node in `main.tscn`) is the world engine:
- Maintains a `Dictionary` of active chunks keyed by `Vector2i` chunk coords; only recomputes when the player crosses a chunk boundary (`world_to_chunk`). `render_distance` (exported, default `5`) gives `(2*render_distance+1)²` active chunks.
- Generates each chunk's mesh, collision, decorative cubes, **and crocodile NPCs** in code — there is no hand-placed scenery. Object/crocodile positions are seeded deterministically from chunk coords **plus the per-run `run_seed`** via `hash(Vector3i(...))`, so a chunk always regenerates identically *within a run* while consecutive runs get fresh worlds (see "Gameplay loop" below).
- Spawned crocodiles are **parented to the chunk MeshInstance3D**, so they are freed automatically when the chunk unloads. Anything you spawn per-chunk should follow this parenting rule or it will leak.

**Chunk generation is time-sliced (one chunk per frame, nearest-first).** `update_chunks` builds only the **safety ring** synchronously — missing chunks within Chebyshev distance ≤ `SYNC_RING` (1) of the player's chunk (9 at startup / after `new_run()`, ≤ 3 on a normal boundary crossing) — so the player never stands over an unbuilt chunk. Every other missing chunk is queued into `pending_chunks` sorted nearest-first (the queue is rebuilt from scratch on each boundary crossing, which dedupes for free), and `_process` dequeues and builds exactly **one** pending chunk per frame — progressive fill hidden behind the fog instead of a multi-second startup freeze. Generation ORDER cannot change content: every chunk's RNG is pure in its own coords + `run_seed`, and the road station cache is pure in `k`. `new_run()` clears the pending queue before rebuilding, and its `update_chunks(Vector2i(0,0))` call synchronously builds spawn + ring 1 — the load-bearing guarantee that the player teleported to `(0,2,0)` lands on solid ground the same frame.

**The ground is one shared `PlaneMesh`, shaded by vertex noise.** `_get_shared_ground_mesh()` (same lazy-getter pattern as `_get_shared_unit_box_mesh`) returns a single 16×16-subdivided `PlaneMesh` used by every chunk (all chunks are the same size), with `cast_shadow` OFF on the ground instance — a flat plane can only shadow itself, so skipping it removes every chunk from the shadow passes. The built-in default ground material is a `ShaderMaterial` on `assets/shaders/ground.gdshader`: a 2-octave world-space value noise computed **per-vertex** (the 16×16 subdivisions provide the vertices) blends two greens; the fragment stage does only the varying lerp, so fill rate is untouched, and world-space input makes the pattern seamless across chunk seams with zero per-chunk work. The `@export var terrain_material` escape hatch remains (now typed `Material`, not `StandardMaterial3D`): a material assigned in the editor wins over the shader.

**Blocks are rendered as one `MultiMeshInstance3D` per chunk, not one `MeshInstance3D` per block.** `create_box()` no longer instances a mesh+material per decorative block; it appends a `{ "transform": Transform3D, "color": Color }` entry to a per-chunk `block_batch` array (threaded through `create_chunk` → `spawn_objects_in_chunk` → `spawn_*` → `create_block` → `create_box`). After generation, `_build_block_multimesh()` builds one `MultiMesh` (shared unit `BoxMesh`, `transform_format = TRANSFORM_3D`, `use_colors = true`) whose per-instance basis is `Basis(Vector3.UP, yaw).scaled_local(dimensions)` and per-instance color comes from **three curated two-color ramps sharing a warm undertone** (the `RAMP_*` consts: sandstone→terracotta, slate→blue-grey, olive→moss), each sampled by one lerp. The material is a single shared `StandardMaterial3D` with `vertex_color_use_as_albedo = true` and `roughness = SHARED_BLOCK_ROUGHNESS` (0.85). **Determinism gotcha:** the ramp swap preserved the RNG draw sequence exactly — same `randi_range(0, 2)` selector, then per branch the same number of `randf_range` calls as the old per-channel-random colors (5/3/5 draws per branch, padding draws explicitly discarded), and `create_box()` still consumes the old per-block roughness `randf_range(0.7, 1.0)` draw (then discards it) — so the chunk RNG sequence, and the whole procedural layout, stays byte-for-byte identical. MultiMesh can't vary roughness per instance, hence the single shared value. `create_box()` carries **three optional, inert-by-default params** — `tilt` and `color_override` (added for artifacts, see below) plus `collide: bool = true`, which when false skips the `CollisionShape3D` and emits the visual batch entry only: tree canopies are visual-only, so a forest pays trunk collision instead of 3–4× that (see "Biomes"). None of the three affects RNG — the colour/roughness draws run identically whatever they are set to.

**Block collision is consolidated into one `StaticBody3D` per chunk.** Visual batching is decoupled from physics: each chunk has one `StaticBody3D` named `"BlockCollision"` (`block_body`, threaded down the same call chain as `block_batch`) that holds every block's `CollisionShape3D` child (a `BoxShape3D` at the block's chunk-local `position`/`rotation.y`). This replaces the old one-body-per-block scheme (~25× fewer block collision nodes). Layer/mask stay at the Godot defaults (1/1), so player collision and crocodile obstacle-avoidance raycasts are unchanged. **Ground collision stays in its own separate `StaticBody3D`** — folding it in would save one node and only muddy the code. A chunk that ends up with no blocks `queue_free()`s its empty `block_body` instead of leaving it in the tree.

**Coins live on a single continuous "coin road", not a per-chunk random scatter.** The road is a deterministic, station-indexed **parametric path** — a pure function of an integer station index `k` and fixed seeds (`ROAD_WORLD_SEED` + the per-run `run_seed`, constant for a whole run — **not** per-chunk RNG), so it lines up seamlessly across chunk seams. Station 0 sits at world origin, so the player spawns on the road. The centerline is built by integrating a per-station heading: `heading[k+1] = clamp(heading[k]*(1-ROAD_RESTORE) + _road_turn(k), ±road_max_heading_deg)` (a deterministic per-station turn plus a restoring bias toward +X). Because `road_max_heading_deg < 90` (asserted), `cos(heading) > 0` always, so the centerline's **X is strictly increasing in `k`** — the road always trends forward while still curving and zig-zagging (full loops / U-turns are intentionally excluded). Coins are **not** placed on the centerline as a single line. Each station instead **scatters a few coins** at ground height (`COIN_GROUND_HEIGHT`) at *random* offsets within a band around the centerline — up to ±band/2 laterally plus a small along-road jitter (`ROAD_COIN_LONG_JITTER`) — so the trail reads as a loose **swath of territory a few coins wide**, not an obvious conga-line. The band width varies between `road_width_min` (10 m) and `road_width_max` (20 m); per station, `road_coin_slots` candidate coins each spawn with probability `road_coin_chance` (≈1 coin/slice on average, so the swath stays sparse and irregular), and `road_coin_spacing` (6 m) is the longitudinal step between scatter slices. The scatter is deterministic — a per-station RNG seeded only from `k` + `ROAD_COIN_SEED` + `run_seed` (see `_road_coins_at`) — so it regenerates byte-identically within a run. `_road_coins_at` returns an array of `{ "pos": Vector3, "gem": bool }` **dictionaries, not bare Vector3s** — each slot rolls one extra `rng.randf()` against `ROAD_GEM_CHANCE` (0.04) to become a rare purple gem worth 10 (`coin.make_gem()`); its only caller is `spawn_coins_in_chunk`. `_road_width(k)` also **narrows the band with distance**: after the oscillating width it lerps toward `road_width_min * ROAD_NARROW_FLOOR_FACTOR` (0.4) over `ROAD_NARROW_STATIONS` (2000) stations — still pure in `k`, and since narrowing only ever *shrinks* the band, the seam `pad` below stays a safe upper bound. Per chunk, `spawn_coins_in_chunk` extends a contiguous, never-reset station cache (`road_stations`) to cover the chunk's widened X-range, then spawns **only** the scattered coins whose `world_to_chunk(coin) == chunk_pos` — each coin is claimed by exactly one chunk, so there are no gaps or duplicates at seams (the scan `pad` is derived from band/2 + jitter so no scattered coin near a seam is missed). **Off-road chunks get zero coins** (this is the incentive to follow the road). A coin that would land on a block footprint perches on the block's top if it's climbable, else is skipped. **Design note:** the forward bias is deliberate — a fully unbounded looping path can't guarantee bounded per-chunk station coverage (a 2D random walk is recurrent), which would break the bounded, deterministic per-chunk generation. If loops are ever wanted, they require the heavier spatial-bucket scheme (bucket every station into a `chunk → stations` dictionary, extend until all active chunks are covered) — noted as a future option, intentionally not built now.

**Rare "lost civilization" artifacts break up the field (~1 chunk in 20).** `spawn_artifact_in_chunk` (called from `create_chunk` **after** `spawn_objects_in_chunk` and **before** `_build_block_multimesh`, so artifact stone joins the chunk's single MultiMesh + single `BlockCollision` body) builds one of **five** code-built landmarks: leaning half-buried monolith with glowing rune strips, broken arch of floating stones, circle of tilted standing stones round a glowing altar slab, half-buried colossus head with emissive eyes, spiral of steps to nowhere. Placement is `_artifact_at(chunk_pos)`, a **pure function** using its own **independent hash stream** — `hash(Vector3i(chunk.x * 73856093, chunk.y * 19349663, run_seed ^ ARTIFACT_SALT))`, the `_boss_at` / `_road_coins_at` pattern — so it consumes **zero** draws from the chunk RNG and the other ~19 chunks in 20 generate byte-identically to before artifacts existed. It rolls `ARTIFACT_CHANCE` (0.05), then up to `ARTIFACT_PLACE_TRIES` (4) candidate spots, accepting the first at least `ARTIFACT_ROAD_CLEARANCE` (14 m) from the road centerline via `_road_lateral_distance()` — that rejection is what produces the **off-road bias** and the hard "never on the centerline" rule (measured: ~1 artifact per 24 chunks after rejections). **All solid stone routes through `create_box`**, which grew two **optional, inert-by-default** params for this: `tilt` (rotation about the local X axis applied after yaw as `Basis(UP, yaw) * Basis(RIGHT, tilt)`, used identically for the visual basis and the `CollisionShape3D` transform so a leaning stone's collision matches) and `color_override` (used only when `a > 0`, giving artifacts the weathered `ARTIFACT_STONE_*`/`ARTIFACT_MOSS` greys — deliberately distinct from the warm `RAMP_*` block ramps). Glow is the only extra geometry: at most `ARTIFACT_MAX_ACCENTS` (4) real `MeshInstance3D`s per artifact via `_spawn_artifact_accent`, sharing one unshaded emissive material (`_get_artifact_glow_material`, cyan, energy 3.0 — above `main.tscn`'s `glow_hdr_threshold` 0.85) with `cast_shadow` OFF. **Reward:** 3-5 ordinary coins on a ring round the base plus **exactly one gem** (`coin.make_gem()`, before `add_child` per coin.gd's contract) at the centre, offset by the shape's `gem_offset` for the two shapes whose centre is solid stone. These are ordinary chunk-local coins — the road station-claim logic is untouched. **Ordering gotcha:** the reward coins are settled through `_settle_coin_y` **before** the artifact's own footprint is appended to `obstacles`; settling after would perch them on the footprint circle's top, floating them metres up over the three mostly-hollow shapes. The footprint is appended last (`climbable = true`), so crocodiles avoid the artifact and road coins perch on it like any block. **Skipped honestly:** the optional proximity shimmer loop — `sound_manager.get_loop_player()` returns a non-positional `AudioStreamPlayer`, so a per-artifact hum would need a new positional audio path plus a per-frame proximity scan.

**Rare nomad camps — dome-hut villages round a fire pit (~1 chunk in 31).** `spawn_camp_in_chunk` is the artifact pattern applied to a *lived-in* landmark instead of a ruin: called from `create_chunk` **after `spawn_biome_content_in_chunk` and before `_build_block_multimesh`**, so 3–6 bone-white dome huts (2–3 stacked shrinking `create_box` tiers, the top one shortened into a cap, plus a dark doorway box facing the fire), a `CAMP_FIRE_STONES` (7) ring of dark stones, crates and tether posts all join the chunk's **single MultiMesh and single `BlockCollision` body** — a whole village costs **one** extra draw call and **zero** extra physics bodies. That one extra is the fire's ember: `_spawn_artifact_accent` grew an **optional trailing `material` param** (null keeps the artifacts' cyan glow, so every existing call site is unchanged) and camps pass `_get_camp_ember_material()` — a second lazily-created shared unshaded emissive material, **warm orange, energy 2.5**, deliberately the opposite temperature to the artifacts' cold cyan, and one material for every ember ever spawned. The palette (`CAMP_HUT_A`/`CAMP_HUT_B` bone-white, `CAMP_STONE`, `CAMP_WOOD`) is likewise distinct from both the warm `RAMP_*` block ramps and the artifacts' grey-green. Fire stones and doorways pass `collide = false` (visual-only clutter); huts, crates and posts collide.
- **Placement is split across two functions, and the split is load-bearing.** `_camp_at(chunk_pos)` is the pure rarity roll on its own independent hash stream — `hash(Vector3i(cx * 40960001, cy * 26463089, run_seed ^ CAMP_SALT))`, coordinate primes deliberately different from the object/artifact (73856093 / 19349663) and biome (83492791 / 15485863) streams — returning `{}` or `{ "seed": int }`; it consumes **zero** draws from the chunk RNG. It holds **no candidate loop**: when it runs the chunk has no geometry yet, so the only tests available are road + river, which reject almost nothing (measured: 11 of 121 chunks), while the test that actually rejects is overlap with the chunk's ~12 scattered blocks. With the loop there, ~9% of rolled camps were built and camps landed ~10× rarer than intended. The `CAMP_PLACE_TRIES` (4) loop therefore lives in `spawn_camp_in_chunk`, where `obstacles` exists, and each try is judged by `_biome_spot_ok(chunk_center, x, z, CAMP_RADIUS 9.4, CAMP_ROAD_CLEARANCE 22, obstacles)` — the existing single home of the river + road-clearance + overlap rule. Measured survival is 14% (86% of rejections are overlap), so `CAMP_CHANCE` is tuned to **0.18** → ~1 camp per 31 chunks. Every try failing means **no camp** — a camp shoved through a mountain massif reads worse than a chunk without one.
- **Crocodile exclusion is one footprint, not a special case.** The camp appends a single round `CAMP_RADIUS` (9.4 m) **non-climbable** footprint at its centre — one circle, no per-hut footprints, because `CAMP_RADIUS` is picked to bound the widest hut on the outermost ring (`CAMP_HUT_RING_MAX` 6.5 + hut radius 2.86 = 9.36 ≤ 9.4), which is also what makes the placement test a true bound on the stone it admits — and `spawn_crocodiles_in_chunk` already rejects candidates within `ob.radius + min_object_clearance` of a footprint — so a camp reads as a calm pocket with **no edit to the crocodile spawner and no shifted RNG draw** (its retry budget absorbs the rejections).
- **Boss exclusion is by construction, not by code.** `CAMP_ROAD_CLEARANCE` (22) **must** exceed `CAMP_RADIUS` (9.4) `+ BOSS_LATERAL_MAX` (4) = 13.4: bosses sit within `BOSS_LATERAL_MAX` of the road centerline and camps at least `CAMP_ROAD_CLEARANCE` from it, so a boss can never stand in a camp — `spawn_bosses_in_chunk` is **untouched**. Likewise `CAMP_EDGE_MARGIN` (12) > `CAMP_RADIUS` (9.4) keeps a whole village inside its own chunk, never straddling a seam. Re-check both inequalities if any of those constants are retuned.
- **Reward: 2–4 ordinary coins by the fire and deliberately NO GEM** — the guaranteed gem stays the artifacts' distinction, so "an ancient prize worth a detour" doesn't flatten into "a village you walked through". Same **ordering gotcha** as artifacts: the coins settle through `_settle_coin_y` **before** the camp footprint is appended, or the non-climbable 9 m circle would skip every one. They can't collide with the road's station-claim logic either — 22 m of clearance versus a `road_width_max / 2` (10 m) scatter band.

### Player: character switching + procedural animation
`scripts/player_controller.gd` (a `CharacterBody3D`) is the player. Two non-obvious systems:
- **Character switching** (E key): cycles the `CHARACTERS` array, freeing the old model and instancing the new `.tscn` under the `$CharacterModel` node.
- **Procedural limb animation**: there is no `AnimationPlayer`. After loading a character, `setup_animation_references()` looks up child nodes **by exact name** — `Body`, and under it `LeftArm`/`RightArm`/`LeftLeg`/`RightLeg`. Walk/jump/idle poses are driven by sine waves on those nodes' rotations. **Any new playable character scene must use this exact node naming** or it will load but stay frozen.

### First-person view toggle (C key)
Pressing **C** (the `toggle_camera` action, polled with `is_action_just_pressed` in `_physics_process` so synthesized touch input works) toggles between the shipped 3rd-person view and a first-person view from the active character's eyes. Design rules, all in `player_controller.gd`:
- **One camera on a collision-aware boom.** The rig is `$CameraPivot/CameraArm/Camera3D`, where `CameraArm` is a `SpringArm3D` (`spring_length` 8.25, −14° pitch; the camera keeps a residual −1° so the shipped framing is visually identical to the old fixed `(0,2,8)` offset). The arm clamps its length against world geometry, so backing into a block slides the camera in instead of clipping through; `_ready()` calls `camera_arm.add_excluded_object(get_rid())` so it never collides with the player's own capsule. `_apply_view_mode()` is idempotent and does all the work: FP sets `camera_arm.spring_length = 0.0` and `camera_arm.transform = Transform3D(Basis.IDENTITY, _first_person_eye_position())` (zero length ⇒ no collision cast ⇒ FP bypasses the arm for free; identity basis + zeroed camera residual pitch make the pivot's mouse-look pitch alone the look pitch) and hides `$CharacterModel`; 3rd person restores the *cached* arm transform + spring length (`third_person_arm_transform`/`third_person_arm_length`, captured in `_ready()`) and re-shows the model. Mouse-look needs no changes: it only drives body yaw + pivot pitch, which serve both views.
- **Eye height tracks Teibi's scale.** `_first_person_eye_position()` derives eye Y from `collision_shape.scale.y` × `FIRST_PERSON_EYE_HEIGHT` (1.65), so small/giant Teibi looks from the right height; `_apply_teibi_scale()` and `set_active_character()` both re-run `_apply_view_mode()` when `first_person` (cheap, idempotent, defensive).
- **SpringArm gotcha — nothing may write `camera.position`.** A `SpringArm3D` overrides its children's local position every physics frame (it slides them along its local Z), so any code that sets `camera.position` is silently fought and undone. The bite shake therefore drives `Camera3D.h_offset`/`v_offset` (view-space slides of the lens, unaffected by the arm, identical in both views) and settles both back to 0.0. Any future camera motion must use those offsets or move the arm/pivot — never the camera's own transform.
- **Speed FOV + eased keyboard turn.** `camera.fov` eases each frame from `FOV_BASE` (75) toward `FOV_MAX` (97) as horizontal speed climbs from walk toward Windman's air speed, plus a transient `fov_punch` (Air Rush kicks it +12, decaying fast) — a `Camera3D` property, so it applies in both views. Keyboard turning is eased: `handle_turning` banks the turn into `camera_yaw_lag`, applied to `camera_pivot.rotation.y` and decayed at `CAMERA_TURN_EASE` (10/s), so the camera trails a keyboard turn and catches up — while **mouse turns stay 1:1** (they rotate the body in `_input` without touching the lag). The lag is zeroed in `reset_position()`.
- **View mode is a preference:** nothing in `reset_position()` / `restart_game()` / `_respawn_in_place()` touches `first_person` or the camera rig, so FP survives respawn, restart, and character switches. The touch UI has a small "View" button (top-centre, next to the steer toggle in `touch_controls.gd`) firing the same action through `_fire_action()`.

### Mobile / touch controls (web build, phone with no keyboard)
The goal is a **web build playable on a phone with no keyboard**: the player physically *steps* to walk, *tilts/twists* the phone to steer, and taps on-screen buttons for the keyboard-only actions. Three new pieces, all **touch-only** and wired by groups — `player_controller.gd` is essentially untouched.

**The KEY design rule: synthesize the EXISTING input actions, don't add controller code paths.** `player_controller.gd` already reads everything through named actions (`move_forward`, `turn_left`/`turn_right`, `jump`, `switch_character`, `special_ability`). The mobile code **drives those same actions** — analog held actions via `Input.action_press(action, strength)` / `action_release(action)`, discrete buttons via `Input.parse_input_event(InputEventAction)` — so movement, animation, and abilities keep working with **zero** controller changes (the lone exception is the one-line mouse-capture guard below).

The three components:
- **`scripts/mobile_sensors.gd`** (`class_name MobileSensors`, a bare `Node`) — the **sensor abstraction** that hides where motion data comes from. It supports **both** sources behind one source-agnostic API and prefers whichever is delivering live data: **native Godot `Input` sensors** (`get_accelerometer()`/`get_gravity()`/`get_gyroscope()`/`get_magnetometer()`) first, else a **`JavaScriptBridge` DOM shim** (`window.addEventListener('devicemotion'/'deviceorientation', …)` polled into GDScript). Public API: `enabled`, `has_data()`, `linear_accel()` (gravity removed — the *step* signal), `tilt()` (roll/pitch vs neutral — the *steer* signal), `yaw()` (twist vs neutral, absolute compass alpha when present, else integrated gyro), `request_permission()`, `calibrate()` (capture current pose as neutral). **iOS gotcha:** Safari fires **no** motion events until `DeviceMotionEvent.requestPermission()` is granted from a *user gesture* in a *secure (HTTPS) context* — `request_permission()` feature-detects this and only attaches listeners on `'granted'`. (GitHub Pages is HTTPS so it works there; a plain-`http` LAN host via `./serve.sh` may not grant motion on iOS.) **GC gotcha:** the JS callbacks are stored in member vars (`_js_motion_cb`/`_js_orientation_cb`) so they survive garbage collection — a dropped reference silently detaches the listeners. Every JS touch is gated behind `OS.has_feature("web")`, so on desktop/editor native reads zero, `has_data()` is false, and nothing throws.
- **`scripts/mobile_input.gd`** (a bare `Node` added once under `Main` in `main.tscn`, like `CrocodileLODManager`, in group `"mobile_input"`) — the **driver**. It owns a `MobileSensors` child and each frame: runs **step peak-detection** on `linear_accel().length()` (rising-edge crossing of `STEP_ACCEL_THRESHOLD` + `STEP_MIN_INTERVAL` refractory) feeding a decaying `walk_energy` → drives `move_forward` at an analog strength; and computes **steering** (tilt-roll default / twist-yaw toggle) through a deadzone→scale → `turn_left`/`turn_right`. Public API for the UI: `enable()`/`disable()`, `calibrate()`, `set_steer_mode(mode)` (also recalibrates — the toggle doubles as a re-zero, important because twist-yaw drifts), `request_permission()`. **It is idle unless `active`:** `_physics_process` early-returns while `!active`, so it never writes `Input` on desktop and the keyboard owns the actions; `disable()` releases any held action so nothing latches. `enable()`/`set_steer_mode()` call `calibrate()` so steering is centred from however the player is holding the phone. The `STEP_*` and `STEER_*` constants at the top are **starting defaults** meant to be tuned on a real device (Task 6 could not — no hardware in the build env).
- **`scenes/ui/touch_controls.tscn` + `scripts/touch_controls.gd`** (a `Control` under the `HUD` `CanvasLayer`) — the on-screen UI. Buttons (built in code in `_build_ui()`): **Jump**, **Special (F)**, **Switch (R)** stacked bottom-right; a small **steer-mode toggle** top-centre; and a first-run **"Tap to enable motion controls"** full-rect overlay that satisfies the iOS permission gesture then `enable()`s the driver and hides. It finds the driver via the `"mobile_input"` group (no hard refs, like `ability_hud.gd`).

**CRITICAL gotcha — `switch_character` is handled in `player_controller._input()`, NOT polled.** `Input.action_press("switch_character")` sets only the *polled* state and would never dispatch an `InputEventAction` through `_input()`, so the switch would silently not fire. Its button **must** use `Input.parse_input_event(InputEventAction)`, which flows the synthetic event through the full pipeline (including `_input()`). `touch_controls.gd` funnels **all three** action buttons through one `_fire_action()` → `parse_input_event` path for consistency (a pressed event now, a matching released event flushed at the top of the **next** `_process` frame via a small `_actions_to_release` queue — a guaranteed-later frame, not a same-frame `call_deferred`, so the press reliably lasts one full frame and `is_action_just_pressed`/`_input()` each see exactly one press).

**Live on-device tuning panel (`scripts/mobile_settings_panel.gd`, a `Control` under the `HUD` `CanvasLayer`, built fully in code like `touch_controls.gd`).** Because no hardware was available when the controls were written, the `STEP_*` / `STEER_*` tunables are **no longer `const`** — they are runtime-adjustable `var`s on `mobile_input.gd` (each starts at a `DEFAULT_*` const so behaviour is byte-for-byte identical until a slider is moved). A small **⚙ Tune** button (top-left, below the lives HUD) opens a translucent panel with a **live diagnostics read-out** (sensor source `native`/`js`/`none`, `accel now`/`peak`, `walk_energy`, step count, tilt/yaw degrees — the `peak` is the number to set the step threshold just under), **one slider per tunable** (step threshold/power/decay/min-interval, steer deadzone/full-angle), an **Invert steering** checkbox (negates the signed steer strength — fixes a reversed-feel phone), plus **Recalibrate**, **Reset to defaults**, and **Close**. The panel talks to the driver only through the `"mobile_input"` group via its public API: `get_tuning()` / `set_tuning(key, value)` / `reset_tuning_to_defaults()` / `get_diagnostics()` / `recalibrate()` (a passthrough to `MobileSensors.calibrate()`, re-added because it's now a live UI affordance). **Persistence:** `set_tuning()` (and the load in `_ready()`) read/write a `ConfigFile` at `user://mobile_tuning.cfg` — on web `user://` is IndexedDB-backed, so a player's dialled-in feel **survives a page reload**; a missing file just keeps the defaults (first-run save does not error). `MobileSensors.current_source()` reports which source last fed data, for the diagnostics line.

**Gating convention (matches the project's "visual/behavioral changes are platform-gated" rule):** the UI's visibility is gated on `DisplayServer.is_touchscreen_available()` (plus a web `matchMedia('(pointer: coarse)')` fallback behind `OS.has_feature("web")`); the driver writes no `Input` when disabled; and `player_controller._ready()` **skips mouse capture** when `is_touchscreen_available()` (the only edit to the controller — `Input.set_mouse_mode(MOUSE_MODE_CAPTURED)` is wrapped in `if not DisplayServer.is_touchscreen_available():`). On desktop the touchscreen probe is false everywhere, so the UI is hidden, the driver never enables, and keyboard+mouse play is **byte-for-byte unchanged**. The tuning panel is gated by the same `MobileSensors.is_touch_session()` rule, so it too is hidden and inert on desktop.

**Debug keys (editor/desktop testing, all outside the project input map like F3):** **F4** toggles the `MotionDebug` sensor readout (`scripts/motion_debug.gd`, a `Label` under `HUD`; hidden by default in release/web, starts visible only in `OS.is_debug_build()` — it prints raw `Input.*` sensors plus the `MobileSensors` API output); **F5** force-enables the `mobile_input` driver; **F6** force-shows the touch UI; **F7** force-shows the tuning panel's ⚙ gear.

### Per-character special abilities (F key)
Each character has **one signature power**, fired with **F** (the `special_ability` input action, defined in `project.godot`). All abilities live in `player_controller.gd` under **SECTION 8** and share one mechanism: `try_activate_ability()` dispatches on the current character name, and every ability is gated by a **per-character cooldown** (`ability_cooldowns: Array[float]`, one slot per `CHARACTERS` entry, durations in the `ABILITY_COOLDOWN` dict). The abilities:
- **windman → Air Rush**: launches up + forward and flies at `WINDMAN_AIR_SPEED` (≈5× walk) with gravity softened by `WINDMAN_GRAVITY_FACTOR` for `WINDMAN_BOOST_DURATION`. Implemented by `windman_boost_timer`, read in the gravity step and in `calculate_current_speed()` (boost speed applies **only while airborne**).
- **primm → Phase Step**: an instant forward blink that passes *through* a block and is **guaranteed to land in open space on the far side** — it never gets stuck inside geometry. Rather than a blind fixed hop it scans outward from `PRIMM_BLINK_DISTANCE` in `PRIMM_BLINK_STEP` increments (up to `PRIMM_BLINK_MAX_DISTANCE`) for the first spot where the body fits, probing via `_is_body_blocked_at()` (a sphere at capsule-centre height so the flat ground never counts as blocked). If nothing is clear within reach, the blink doesn't fire and costs no cooldown.
- **teibi → Resize**: cycles normal → small → giant → normal (`teibi_size_state`). `_apply_teibi_scale()` scales **both** `$CharacterModel` and `$CollisionShape3D`, moving the collision node so the capsule's **bottom stays pinned to the ground** at any scale (no sinking/launching). Giant form sets `is_giant` (exposed to crocodiles via `crushes_crocodiles()`) and **can't jump** (the jump step checks `not is_giant` — too heavy). An altered form (small **or** giant) **auto-reverts to normal after `TEIBI_FORM_DURATION` (10 s)** via `teibi_form_timer` ticked in `_update_ability_timers()`, so Teibi can never get stuck transformed; the timer is a *total* budget for the whole excursion (a small↔giant switch does not refill it). `_revert_teibi_to_normal()` is the shared snap-back used by the timeout, character switch, and respawn.
- **phoboman → Stink Wave**: spawns staggered expanding `ability_effect.gd` waves and calls `flee_from(origin, PHOBOMAN_FLEE_DURATION)` on every node in the `"crocodile"` group.

Two cross-cutting pieces:
- **`scripts/ability_effect.gd`** — a self-building, self-freeing expanding/fading sphere "wave". Spawned by attaching the script to a bare `MeshInstance3D` (`set_script` + `setup(color, radius, lifetime, delay)`), parented to the player's parent so it outlives nothing and leaks nothing. Reused for the stink wave plus small flashes for the gust/blink.
- **`scripts/ability_hud.gd`** (the `AbilityHUD` `Control` under the `HUD` `CanvasLayer`, top-right under the coin counter) — an asset-free radial cooldown dial drawn in `_draw()`. It finds the player via the `"player"` group and reads the contract methods `get_ability_name()` / `get_ability_cooldown_ratio()` / `get_ability_remaining()` / `is_ability_ready()`.

Transient ability state (air boost, giant form, odd size) is cleared on respawn (`_reset_ability_states()` in `reset_position()`) and on character switch (in `set_active_character()`), so a power never bleeds across a death or a swap.

### Two parallel enemy implementations (important gotcha)
There are **two** enemy AI scripts with different contracts; know which one you're touching:

| | `piglet_crocodile_ai.gd` | `enemy_controller.gd` |
|---|---|---|
| Scene | `scenes/characters/piglet_crocodile.tscn` | `scenes/enemies/cyborg_piglet.tscn` |
| Groups | `crocodile`, `enemy` | `enemies` |
| Behavior | Wanders, **chases player** within `DETECTION_RADIUS` (loses scent when player jumps / leaves ground); crocodiles are **solid to one another** (bump and push apart, no overlap) | Wanders only |
| On player hit | calls `player.reset_position()` | calls `player.game_over()` |
| Spawned by terrain? | **Yes** | **No** |

`piglet_crocodile_ai.gd` is the live enemy: it's what `endless_terrain.gd` spawns and it calls `reset_position()`, which the player implements. `enemy_controller.gd` / `cyborg_piglet.tscn` are newer and **not yet wired in** — nothing spawns them, and their death contract `player.game_over()` does **not exist** on the player (only `reset_position()` does), so their collision is currently a no-op. If you intend to make cyborg piglets functional, either spawn them from the terrain and add a `game_over()` method, or converge them onto the existing `reset_position()` contract.

`piglet_crocodile_ai.gd` also implements two hooks for the player's special abilities (see "Per-character special abilities"): `flee_from(origin, duration)` makes it turn tail and run from the player (a `is_fleeing` state that **overrides chase/wander**, used by Phoboman's Stink Wave; a fleeing croc is harmless), and in `_on_player_collision` it checks `player.crushes_crocodiles()` first — if true (giant Teibi) it `queue_free()`s itself instead of biting.

**Per-crocodile variety.** In `_ready()` each crocodile rolls two independent randoms so the pack isn't uniform: a single **speed** multiplier (`SPEED_RANDOM_FACTOR`, ±50%) applied to *both* `move_speed_instance` and `chase_speed_instance` (so a "fast" croc is fast at everything yet its chase still outpaces its own wander), and a uniform **size** scale (`SIZE_RANDOM_FACTOR`, ±25%) applied to the whole `CharacterBody3D` via `scale` — this grows/shrinks the visual model and the physics capsule together, and gravity settles each croc onto the ground regardless of size. The model's own local scale stays `1`, so `model_base_scale` and the procedural body animation are unaffected by the body scale. These are rolled from the per-instance `rng` (which is `randomize()`d), so size/speed are **not** deterministic at all — unlike the chunk-seeded *positions*, which are deterministic within a run. `_ready()` also applies the **difficulty gradient**: `chase_speed_instance` is multiplied by `1.0 + clampf(absf(global_position.x) / DISTANCE_SPEED_SCALE_DENOM, 0.0, DISTANCE_SPEED_SCALE_MAX)` (+60% at 3 km; valid in `_ready` because the terrain parents the croc before `_ready` runs), then clamped to `MAX_CHASE_SPEED` (8.5) — without the cap a top-rolled far croc (5.5 × 1.5 roll × 1.6 distance = 13.2) would outrun even a *running* player (slowest character runs at 9.0), breaking the running-escapes hatch, and `BASE_CHASE_SPEED` is **5.5 — deliberately above WALK_SPEED 5.0** so a walking player gets caught and must run or use abilities to escape. **Crocodiles are solid to each other:** the scene sets the body's `collision_mask = 3` (layers 1 **and** 2), where layer 2 is the crocodile layer — so `move_and_slide` pushes two bumping crocodiles apart instead of letting them overlap. `_handle_collisions()` deliberately ignores crocodile-vs-crocodile contacts (no eat-on-touch); the physical push is the whole behaviour. The player stays `mask = 1`, so the *player* still passes through crocodiles physically — player damage is driven entirely by the crocodile's own `_handle_collisions` detecting the player, unchanged.

**Boss crocodiles (deterministic road-station giants).** Rare "boss" crocodiles stand on the coin road — same scene, same AI, differing only in flags set by `setup_as_boss(body_scale)` in `piglet_crocodile_ai.gd`. **Call-order contract:** the terrain calls `setup_as_boss` on the instance **before** `add_child`, so `_ready()` sees `is_boss` and branches — bosses skip *both* per-instance random rolls (speed and size; their size comes from the deterministic schedule, their chase speed is `minf(BOSS_CHASE_SPEED 7.0 × distance factor, MAX_CHASE_SPEED 8.5)` — walking (5.0) loses, running (9.0+) escapes). Placement lives in `endless_terrain.gd` (`_boss_at(i)` / `spawn_bosses_in_chunk`): boss index `i ≥ 1` owns road station `k = i * BOSS_INTERVAL_STATIONS` (50 stations ≈ 300 m; no boss at spawn), positioned ahead of the station along the heading plus a small lateral offset drawn from an RNG seeded `hash(Vector3i(i, BOSS_SEED, run_seed))` — its **own independent hash stream** like `ROAD_COIN_SEED`; it never consumes a draw from any existing chunk/coin/croc RNG sequence, so the rest of the world regenerates byte-identically. Size schedule: `minf(BOSS_BASE_SCALE 2.5 × (1 + (i−1) × BOSS_GROWTH 0.35), BOSS_MAX_SCALE 6.0)` → 2.5, 3.375, 4.25, 5.125, 6.0, 6.0, … Chunk-claim spawning exactly like road coins (only the chunk where `world_to_chunk(pos)` matches spawns it, parented to the chunk mesh), so outrunning far enough despawns the boss with its chunk — "you escaped it". Behavior flags: `flee_from()` early-returns when `is_boss` (Stink Wave immunity — group `"crocodile"` membership is **kept**, the wave finds bosses and they shrug it off); detection radius is `BOSS_DETECTION_RADIUS` 25.0 (**must stay well below `SIM_RADIUS` 45** — same always-awake-when-dangerous invariant as regular crocs); `_on_player_collision` checks `is_boss` **above** the giant-Teibi crush block, so a boss bites giant Teibi instead of being crushed (assumption: a 2.5x+ boss out-sizes giant Teibi). Visuals: `ToonShading.apply_boss_to_mesh` installs a darker red-shifted variant from its own static cache (one shared duplicate per source material, never per-boss), and the per-mesh `visibility_range_end`/margin are scaled by `boss_scale` so a 6x boss doesn't pop in at 60 m. On the not-chasing → chasing transition a boss fires `play_boss_growl()` on the sound manager (null-safe group lookup). Bosses participate in LOD sleep like any croc.

### Crocodile simulation LOD (sleep distant crocodiles, never remove them)
`scripts/crocodile_lod_manager.gd` is a `Node` (named `CrocodileLODManager`, added once under root `Main` in `main.tscn`) that keeps the in-browser frame rate up by **putting distant crocodiles to sleep**. It holds no hard references — it finds the player via the `"player"` group and crocodiles via the `"crocodile"` group. On a throttled tick (`SCAN_INTERVAL = 0.11`, ~9 Hz, **not** every frame) it compares each crocodile's squared distance to the player against `SIM_RADIUS = 45.0`, with a `HYSTERESIS_MARGIN = 5.0` dead-band (wake within 45 m, sleep only beyond 50 m) so a body on the boundary doesn't flicker. It calls `croc.set_lod_active(bool)` **only on a state change**.

The crocodile side of the contract lives in `piglet_crocodile_ai.gd`: it has `var lod_active := true` and `set_lod_active(active)`, which zeroes `velocity` and calls `set_physics_process(active)` — a slept croc's `_physics_process` is not dispatched at all (~460 saved script dispatches per physics tick across the pack). The `if not lod_active: velocity = Vector3.ZERO; return` early-return at the top of `_physics_process` stays purely as a backstop. A slept crocodile stays exactly put with all heading/chase/phase/confinement state preserved, and resumes seamlessly on wake. (The croc scene's old `HitBox` Area3D is **gone** — the script itself documented that nothing ever connected to it, so it was deleted; `set_lod_active` no longer toggles any Area3D monitoring.)

Independent of the simulation sleep, crocs also get a **pure draw cull**: `_ready`'s `_style_model_meshes()` walk sets `visibility_range_end = VISUAL_CULL_DISTANCE` (60) / `visibility_range_end_margin = VISUAL_CULL_MARGIN` (8) on every mesh in the model subtree (and applies `ToonShading.apply_to_mesh` — see "Art-directed look" below), so beyond ~60 m the renderer simply skips the meshes (works in `gl_compatibility`; the universal fog hides the pop). Two independent radii by design: LOD sleep at 45/50 m (simulation), draw cull at 60/8 m (rendering) — the cull is wider than the sleep radius, so a visible croc is never a frozen-mid-stride sleeper close up. Entity counts unchanged in both cases.

**The same scan publishes the danger telegraph.** Inside `_scan_crocodiles()` (zero extra passes) the manager tracks the minimum distance among crocs whose `is_chasing` is true (guarded with `"is_chasing" in croc`) and pushes `sqrt` of it — or `INF` when nobody is hunting — to the `"danger_vignette"` group node via a null-safe `set_danger_distance(d)` call. `scripts/danger_vignette.gd` (a `Control` under the HUD `CanvasLayer`, stacked BELOW `HitFlash` so a bite flash still reads on top) turns that into a red screen-edge vignette (one `ColorRect` with a tiny code-built `canvas_item` shader; alpha eased per frame so the 9 Hz scan doesn't step visibly; `visible = false` when clear so the shader costs nothing) and drives the sound manager's `"heartbeat"` loop — `play()` when danger appears (gated on `is_unlocked()`), `stop()` when it clears, with `pitch_scale` 1.0 → 1.8 and `volume_db` −18 → −6 as the chaser closes `DETECTION_RADIUS` → 0. This works because chasing crocs are always awake (`SIM_RADIUS` ≫ `DETECTION_RADIUS`), so the scan sees every chaser; bosses are in the same group and expose `is_chasing`, so they trigger it with no extra code.

The manager also gates **coin animation** on the same ~9 Hz tick (it is now the small animation/simulation LOD manager for crocs + coins; name kept for history): every node in the `"coin"` group gets `set_process(false)` beyond `COIN_ANIM_RADIUS` (30 m) from the player and `set_process(true)` within, with the same hysteresis (`COIN_HYSTERESIS = 5.0`) and only-on-state-change discipline. Distant coins just stop spinning/bobbing (invisible at 30 m+); collection is Area3D-signal driven and does not depend on `_process`, so a frozen coin still collects normally.

Two non-negotiable invariants:
- **`SIM_RADIUS` (45) must stay well above `DETECTION_RADIUS` (15).** Any crocodile that could detect, chase, or touch the player is always fully awake, so near-player behavior is byte-for-byte identical; only crocodiles far out of reach are frozen. If you change `DETECTION_RADIUS`, keep `SIM_RADIUS` comfortably larger (it is currently 3× plus the hysteresis buffer).
- **Crocodiles are slept, never removed.** The manager only flips a flag — it never `queue_free()`s a crocodile — so entity counts are unchanged. The F3 perf overlay's `Crocs (active/total)` line proves this: active is a small handful while total stays large.

### Player death / lives / respawn contract
The player has a **lives system** (`MAX_LIVES = 3` starting hearts, drawn top-left by `scripts/lives_hud.gd`; coins can push `lives` up to `LIVES_CAP = 5` — see "Gameplay loop" below). `lives_hud.gd` holds **no `MAX_LIVES` constant of its own** — it reads the pip total from the player (`maxi(player.MAX_LIVES, player.lives)`) so a 4th/5th heart renders and the old duplicated-constant sync bug can't return. The damage entry point is still the crocodile calling `player.hit_by_crocodile()`, which plays the brief "caught" freeze/flash/shake. When that window ends, `_on_caught_finished()` spends one life and branches:
- **Lives remain → soft respawn in place** (`_respawn_in_place()`): the player stays exactly where it fell and **keeps all coins** — losing a life is the only penalty. The grace period is split into two phases: first a **frozen** window (`RESPAWN_GRACE_DURATION = 1.5` s, one-decimal centred countdown via the `respawn_label` group node) with ability state cleared and crocodiles swept within `SPAWN_SAFE_RADIUS` (one more sweep on the final frame so nothing can bite on the first unfrozen frame); then control returns but the player stays **invulnerable while blinking** for `RESPAWN_BLINK_DURATION` (2.5) more seconds — `respawn_blink_timer` toggles `character_container.visible` on a `RESPAWN_BLINK_CADENCE` (0.1 s) cadence (skipped in first-person, where the model is already hidden) and visibility is restored through the idempotent `_apply_view_mode()` when it expires, so the current view mode is always respected.
- **No lives left → game over** (`_trigger_game_over()`): freezes the player, frees the mouse cursor, updates/saves the best-run records, and raises the Game Over screen (`scripts/game_over_ui.gd`, found via the `game_over_ui` group) via `show_game_over(coins, distance, best_distance, best_coins, is_new_best)` — distance is the headline, with the coin tally, a "Best: NNNm / NN coins" line, and a tween-pulsed "NEW BEST!" flash when the distance record fell. **Enter/Space also restarts**: `_unhandled_input` treats `ui_accept` (which covers both keys out of the box, no `project.godot` change) as the **Play Again** button, which calls `player.restart_game()` — that wipes coins/distance/streak, refills lives, recaptures the mouse, calls `terrain.new_run()` (via the `"terrain"` group) to regenerate the world with a fresh seed, then `reset_position()`.

Invulnerability is enforced in one place: `hit_by_crocodile()` early-returns while `is_caught`, `is_respawning`, `is_game_over`, **or `respawn_blink_timer > 0.0`** (the blink phase); `restart_game()` and `reset_position()` both zero the blink timer (and restore visibility via `_apply_view_mode()`) so the state never leaks across a restart. The "caught" flash comes from `scripts/hit_flash.gd`, whose `flash()` now takes an optional color argument (defaulting to the bite red), so other systems can reuse the full-screen flash in their own tint. `reset_position()` is now only the **hard reset to spawn** `(0,2,0)` (teleport + zero velocity/rotation + `clear_nearby_crocodiles()` + wipe coins + `_reset_ability_states()`) used by `restart_game()` and kept as the crocodile's legacy fallback — a normal bite no longer teleports to origin or clears coins. (Giant-form Teibi still **crushes** crocodiles on contact via `crushes_crocodiles()`, so those never reach the bite path at all.)

### Gameplay loop (score, per-run seed, difficulty gradient)

**Per-run world seed — the determinism contract.** `endless_terrain.gd` holds `var run_seed: int`, rolled once in `_ready()` from a private `RandomNumberGenerator` (never the global RNG) and mixed into **all five** deterministic hash sites as the third component of a `Vector3i` — the chunk object seed, ground-croc seed, platform-croc seed, `_road_hash01(k)`, and the `_road_coins_at(k)` RNG seed. Within a run `run_seed` is constant, so every seed site stays a pure function of (chunk coords | `k`) and revisited chunks regenerate byte-identically; across runs it differs, so run 2 is a different world. `new_run()` (the only thing that changes it) re-rolls the seed, clears the road station cache back to its empty sentinel, clears the pending-chunk queue, frees every active chunk, and rebuilds around chunk (0,0) — spawn + ring 1 synchronously (so the player teleported to spawn lands on solid ground the same frame), the rest via the one-per-frame progressive fill. The terrain is in the `"terrain"` group; `player_controller.restart_game()` calls `new_run()` through it (with a `has_method` guard) **before** `reset_position()`. If you add a new deterministic spawn site, mix `run_seed` in the same `hash(Vector3i(a, b, run_seed))` shape.

**Distance is the headline score.** `player_controller.run_distance = maxi(run_distance, int(global_position.x))` each physics tick — valid as *distance travelled* because the coin road's X is strictly increasing by construction (see the coin-road section), so no path integration is needed. `coin_hud.gd` shows `Distance: %dm   Coins: %d` live (plus a ` (x%d)` streak suffix when the multiplier exceeds 1). Best-run records (`best_distance`, `best_coins`, tracked as independent maxima) persist via ConfigFile at `BEST_RUN_CONFIG_PATH = "user://best_run.cfg"` (section `"best"`, keys `distance`/`coins`) — same pattern as `mobile_input.gd`'s tuning file: missing on first run is fine, IndexedDB-backed on web so it survives a page reload.

**Coin economy.** `coin.gd` has `value: int = 1` and `make_gem()` — the spawner calls it right after instantiate to make a rare purple gem (~1.6x scale, emissive material duplicated at runtime, never mutating the shared resource) worth 10; collection calls `body.collect_coin(value)`. `collect_coin()` applies a **streak multiplier**: consecutive pickups within `STREAK_WINDOW` (2.5 s) build `coin_streak`; every `STREAK_COINS_PER_STEP` (10) coins add +1 to the multiplier up to `1 + STREAK_MAX_BONUS` (x5). The streak breaks when the window lapses or on a *non-ignored* bite (`hit_by_crocodile()` resets it **after** the invulnerability early-return, so bites during grace don't break streaks). Every `EXTRA_LIFE_COINS` (75) banked grants +1 life up to `LIVES_CAP` (5) — checked with a `while` loop because one gem at high streak can jump multiple thresholds. Characters also have modest speed stats (`CHARACTER_SPEED`, 0.9–1.15x) multiplied into `calculate_current_speed()`'s duck/run/walk returns (not Windman's air-rush speed, which the ability owns).

**Difficulty gradient — all pure functions of position, deterministic within a run:** croc chase speed scales with `absf(global_position.x)` and `BASE_CHASE_SPEED` (5.5) outruns walking (see "Per-crocodile variety"); croc density scales with chunk distance (`spawn_crocodiles_in_chunk` targets `crocodiles_per_chunk + mini(8, absi(chunk_pos.x) / 6)`, cheap because the LOD manager sleeps distant crocs); the coin road band narrows with station index (see the coin-road section). Escape hatches stay: running, jumping (breaks scent), and abilities all beat 5.5.
### Synthesized audio (no asset files)
`scripts/sound_manager.gd` (a `Node` named `SoundManager` under `Main` in `main.tscn`, in group `"sound_manager"`) is the entire audio layer. **Invariant: there are no audio asset files** — every sound is generated in code at `_ready()` as an `AudioStreamWAV` (mono 16-bit PCM at `MIX_RATE = 22050`), so the web build size is unchanged. One-shots play through a round-robin pool of `ONESHOT_PLAYER_COUNT` `AudioStreamPlayer` children (overlapping sounds don't cut each other off); the quiet ambient wind bed (`WIND_VOLUME_DB = -26`, far below the −6..−10 dB one-shots) has its own dedicated looping player.

Public API (all void, all safe to call anytime): `play_coin()` (random `pitch_scale` jitter per pickup), `play_jump()`, `play_land()`, `play_footstep()` (pitch-jittered soft noise "pat", fired from the walk-cycle sine's zero crossings — each sign flip is one foot planting), `play_buzz()` (low square-wave "blocked" buzz — the cooldown-refused F press), `play_crunch()` (harsh noise burst — giant Teibi crushing a croc), `play_ability(character_name)` (per-character pitch via the `ABILITY_PITCH` dict), `play_bite()`, `play_game_over()`, and `unlock_audio()`. Callers never hold a reference — hooks are null-safe group lookups (`get_first_node_in_group("sound_manager")` + `has_method` guard), so any scene run without `Main` stays silent instead of erroring: `coin.gd` and `touch_controls.gd` inline the lookup at their single hook each, while `player_controller.gd` (five hooks) funnels them through its `_sfx(method, arg)` helper. The landing thud fires on the raw floor transition in `update_character_animation()` (before the animation branch chain, so an active sidestep can't swallow it) and is muted during the frozen caught/respawn/game-over windows. (The coin's pickup sound plays through the manager's players, not the coin, because the coin `queue_free()`s itself on pickup.)

**Web unlock gesture rule:** browsers block audio until a user gesture, so every `play_*` early-returns until `unlock_audio()` flips `_unlocked` (which also starts the wind loop). The manager's own `_input()` calls it on the first key/click/touch (then disables input processing), and `touch_controls.gd`'s "enable motion controls" overlay tap calls it explicitly — the guaranteed gesture on mobile web. Don't add a `play_*` path that bypasses this gate.

**Runtime-varied loops:** `get_loop_player(name)` fetches (or lazily creates) a dedicated looping `AudioStreamPlayer` per named ambient bed. Two built-ins: `"wind"` (started by `unlock_audio()`) and `"heartbeat"` — one baked "lub-dub" cycle built in `_ready()` as a `LOOP_FORWARD` `AudioStreamWAV` (`loop_begin = 0`, `loop_end = data.size() / 2` — frames, not bytes, at 2 bytes/frame), which the manager **never plays itself**: the danger vignette owns play/stop/pitch/volume through `get_loop_player("heartbeat")` (see the danger telegraph above). A future system needing a live-modulated loop follows the same pattern — request a name, assign a looping stream, vary `pitch_scale`/`volume_db` per frame — and must check `is_unlocked()` before calling `play()`, because the gesture gate only guards the manager's own `play_*` methods.

### Weather: clouds, storm rain zones, birds
`scripts/weather_manager.gd` (a `Node` named `Weather` under `Main` in `main.tscn`, in group `"weather"`) owns **all** ambient weather in one self-contained file. It is deliberately **not** part of `endless_terrain.gd`: the terrain is the *world* engine and everything it spawns is a deterministic pure function of chunk coords + `run_seed`, while weather is *ambience* — clouds drift across chunk seams, follow the player rather than the grid, and nobody cares whether run 2's sky matches run 1's. So it uses a plain `randomize()`d `RandomNumberGenerator` (same precedent as the crocodiles' per-instance size/speed rolls) and never touches the terrain's hash streams.

- **Clouds.** A fixed pool of `CLOUD_COUNT` (26) blocky clusters (4–9 flattened boxes each) floats at 45–70 m in a `FIELD_RADIUS` (250 m) disc around the player, drifting along one global `WIND_DIR`/`WIND_SPEED` with per-cloud speed variation and a sine bob. A cloud that leaves the disc **in any direction** is **recycled, never freed**: re-rolled and re-placed on the rim *opposite* the side it left by, so the field never depletes and nothing pops in view. **The "any direction" part is load-bearing** — `WIND_SPEED` is 1.6 m/s and `WIND_DIR` is mostly +X while the player runs +X at 5–10 m/s (≈25 during Air Rush), so clouds are in practice left *behind*, never overtaken. An earlier downwind-only test (`to_cloud.dot(WIND_DIR) > FIELD_RADIUS`) therefore never fired: the whole field stranded out of range within ~40 s and the sky stayed empty for the rest of every run, taking `is_raining_at()` — and with it rain particles, the rain bed and both Windman-in-rain rules — down with it. All of it renders as **one `MultiMeshInstance3D`** (shared unit `BoxMesh`, `use_colors`, one `StandardMaterial3D` with `vertex_color_use_as_albedo`) — one draw call for the whole sky. `cast_shadow` is **OFF** on purpose: `directional_shadow_max_distance` is 55 m, so clouds at 45–70 m are outside the shadow range anyway. No transparency anywhere — alpha-blended sky quads that big are mobile fill-rate poison.
- **Storm clouds + rain.** `STORM_CHANCE` (~1 in 7) makes a cloud bigger, dark (`STORM_COLOR`), and gives it a **circular ground rain zone** whose radius is measured from its actual rolled boxes (`RAIN_ZONE_FACTOR` × cluster radius), moving with the cloud. Rain is **one `CPUParticles3D`** (never `GPUParticles3D` — web runs `gl_compatibility`), 120 thin streaks, `local_coords = false` so drops keep falling in world space while the emitter box follows the player. `emitting` flips **only on the enter/exit transition**, so outside a zone the whole rain path costs nothing beyond the manager's own tick.
- **Rain audio.** The rain loop is synthesized **inside the weather manager** (`_synth_rain_stream()` — the same one-pole-noise + crossfaded-seam recipe as `sound_manager._synth_wind()`, with a much brighter filter) and played through `sound_manager.get_loop_player("rain")`, so `sound_manager.gd` needed no edit. A `_rain_mix` 0..1 lerped at `1/RAIN_FADE_TIME` drives both the rain volume and a `WIND_DUCK_DB` duck of the ambient wind bed (whose base volume is *captured*, never assumed); the voice is `stop()`ped once fully faded out, and `play()` is gated on `is_unlocked()` because `get_loop_player` voices bypass the manager's own gesture gate.
- **Gameplay API + the Windman rule.** `is_raining_at(world_pos: Vector3) -> bool` is a flat XZ circle test against the handful of storm clouds — cheap enough to call per frame. `player_controller.gd` uses it through **exactly one** null-safe helper, `_weather_is_raining_here()` (group `"weather"` + `has_method`, same shape as `_sfx()`), in two places: pressing **F** as Windman inside rain fails like a cooling-down press (`ability_hud.flash_blocked()` + `play_buzz`) and **does not consume the cooldown**; and a Windman *already flying* who enters a zone has `windman_boost_timer` zeroed — wet wings, normal gravity resumes mid-air.
- **Birds.** Every `BIRD_INTERVAL_MIN`–`MAX` (60–120 s) a flock of 3–7 birds crosses at 30–40 m and despawns past the field radius: no collision, no AI, no interaction. Each bird is 3 instances (body + 2 wings) in a **second MultiMesh**, parked at zero scale between flocks. Birds are the one thing updated **every frame** rather than on the throttled tick — a ~3 Hz wing beat sampled at 10 Hz would alias into a stutter — which is affordable because ≤21 instances exist only during the rare seconds of a crossing.
- **Perf shape:** everything runs on a throttled `TICK_INTERVAL` (0.1 s, ~10 Hz) tick like `crocodile_lod_manager.gd`; total cost is 2 MultiMeshes (clouds + birds) plus 1 `CPUParticles3D` that only emits inside a rain zone. The F3 overlay is the measure: draw calls should rise by a couple, not dozens. A full-screen darkening `ColorRect` for rain mood was **deliberately skipped** (fill-rate cost for a subtle effect) — noted in the script, trivial to add if the mood falls flat.

### Ambient fauna (migrating herds + herder caravans)
`scripts/fauna_manager.gd` (a `Node` named `FaunaManager` under `Main` in `main.tscn`, in group `"fauna"`) is the whole feature: every so often a family of elephants, a flock of giraffes, or a herder caravan walks across the landscape in the distance. It is **pure scenery** — sibling in spirit to `crocodile_lod_manager.gd`, it finds the player via the `"player"` group (null-safe: no player, no herds) and owns its entities directly.

- **One herd at a time, ever — that is the entire perf story.** `_spawn_herd()` early-returns while `_animals` is non-empty. A herd is at most 8 animals × ~12 boxes, alive only during an event; between events the per-frame cost is one float subtraction on `_event_timer`. Animals are parented to the manager itself, **never to a terrain chunk** — chunk unloading must not free a herd mid-walk. Despawn is a distance check against the **live** player position (`DESPAWN_RADIUS` 150, just past the `FIELD_RADIUS` 140 spawn circle), so "the herd walked past" and "the player ran away" are the same branch. Both radii are bounded by the same terrain-extent argument — the *whole lifetime* has to stay on solid ground, not just the spawn frame.
- **The spawn heading is a rearward cone, not a random compass bearing.** The player runs +X at 5–11 m/s and a herd ambles at 2–3, so a herd heading anywhere near the run direction is simply outrun and despawns behind the camera, unseen. `MIGRATION_HEADING_SPREAD` (±0.6 rad) draws the heading against +X, putting the herd origin ahead down the road so it walks back through the player's area. `FIELD_RADIUS` 140 is likewise a constraint, not taste: the web build's terrain reaches only ~150 m (`WEB_RENDER_DISTANCE` 3 × 50 m chunks), and a herd spawned past that stands over open sky. The migration line is also offset sideways by `MIGRATION_MISS_MIN..MAX` (25–60 m, either side) — the origin sits on the ray *from the player*, so with no offset the herd would walk straight **through** them, guaranteed whenever the player can't step aside (the respawn grace freeze, a pause, the game-over screen). The along-heading setback shrinks by Pythagoras to keep the origin on the `FIELD_RADIUS` circle, so the lateral offset can never push a fresh herd past `DESPAWN_RADIUS` and get it freed on its first frame.
- **The animals join NO group and have NO collision.** This is a hard contract, not a style choice: Phoboman's Stink Wave iterates `"crocodile"` and the LOD manager iterates it too, so a fauna node in any enemy group would be grabbed by both. Animals are plain `Node3D` + `MeshInstance3D` trees with **no per-animal script** — one `_process` on the manager moves and animates all of them, reading only pivot references cached at build time (zero allocations, no `get_node()` in the loop). Walking through a decorative block is the accepted ceiling (`ponytail:` comment names raycast-nudge as the upgrade path).
- **Shared resources: ONE `BoxMesh` + one material per species, in `static var` lazy getters** (same trick as `endless_terrain._get_shared_unit_box_mesh()` and `ToonShading`'s material cache). The feature's material total is a constant 6 (elephant, giraffe, off-white tusk accent, dark patch/horn, herder cloak, pack-beast wool) no matter how many animals ever spawn — **never `duplicate()` a material per animal or per part**. Models are code-built from that unit box, scaled per part; there are no asset files and no Python pipeline. `cast_shadow` is ON for adult body/legs/neck and OFF for small accents (ears, trunk, tusks, horns, patches) and for every part of a calf.
- **Feet rest at y = 0 by construction** — the ground is a flat `PlaneMesh` at y = 0, so fauna needs no raycasts and no terrain queries. If the terrain ever gets height variation, this is the assumption that breaks.
- **Deliberately non-deterministic.** The manager uses its own `randomize()`d `RandomNumberGenerator` and never touches the terrain's `run_seed`. Ambience is not part of the determinism contract — do not wire it in.
- Animation follows `piglet_crocodile_ai._animate_body()`'s idiom, with one improvement: the stride phase is a pure function of **metres walked** (`_herd_travelled * STRIDE_FREQUENCY` + the animal's phase offset), not an accumulator — so feet keep pace with the ground at any walk speed and the phase can never drift. Diagonal leg pairs sit a half-cycle apart (a real trot), the body bobs at **twice** the stride rate, and per-animal phase offsets keep the herd out of lockstep. The body bob is deliberately **offset to stay at or above rest**: the legs hang off `Body`, so a bob dipping below rest would push every foot through the ground plane. The giraffe neck bob composes **on top of the neck's cached rest lean** rather than overwriting it.
- **Herder caravans are the third migration type, and they are just N more records.** `CARAVAN_CHANCE` (0.15) is rolled **first** in `_spawn_herd()`, taking its slice off the top so the existing `ELEPHANT_CHANCE` split stays exactly the elephant/giraffe branch (0.425 each) — one extra branch, not a restructure. A caravan shares the fauna event timer rather than owning one, so the "one herd at a time, ever" perf story is unchanged. `_spawn_caravan()` puts `CARAVAN_HERDERS_MIN..MAX` (2–4) herders at the **front** of the line and `CARAVAN_BEASTS_MIN..MAX` (3–6) laden pack beasts trailing behind, one slot per member stepping `CARAVAN_LINE_SPACING` (2.2 m) back along the heading with `CARAVAN_LINE_JITTER` lateral wobble — the spacing is bounded, not chosen by eye: the line is centred on a herd position that spawns exactly on `FIELD_RADIUS`, so half a full ten-member line (4.5 × 2.2 = 9.9 m) has to fit inside `DESPAWN_RADIUS − FIELD_RADIUS` (10 m) or the tail stands past the web build's ~150 m of terrain, and hands each to the existing `_add_animal(record, offset)` — so formation easing, facing, phase offsets, movement, animation and despawn all come for free with **no new state in `_update_herd` / `_animate_animals`**.
- **The caravan builders return the same species-agnostic record** (`root`/`body`/`legs`/`neck`/`neck_rest`/`trunk`), which is why nothing downstream needed a branch. `_build_herder()` is a torso + head + staff over **two** `_make_leg` hip pivots — the animation loop indexes `LEG_PHASE_OFFSETS` by leg index, so two legs get the 0/π alternating stride for free — with `neck = null` and `trunk = []` (already the elephant/giraffe cases). `_build_pack_beast()` is a woolly body with a shag fringe, four legs in the required FL/FR/RL/RR order, bundles strapped on the back, and a curved neck in the `neck` slot so the existing neck-bob (composed on top of `neck_rest`) drives it. Same shadow discipline as the herds — `cast_shadow` ON for torso/legs/beast body/neck, OFF for staff, fringe, bundles and head nubs — and the same hard isolation contract: **no group, no collision, no reaction to player, crocodiles, abilities or rain.**
- Deferred by design: the elephant trumpet one-shot (a `sound_manager` `play_*` in its synth style is the upgrade path); the caravan bell one-shot, skipped for the same reason plus one more — `sound_manager` voices are non-positional and a caravan spawns ~140 m away, so a bell would misread as coming from the player (the upgrade path is an `AudioStreamPlayer3D` on the lead herder); and caravan↔nomad-camp pathing, which is out of scope (the upgrade path is a nearest-camp query on the terrain).

### Art-directed look (main.tscn + ToonShading)
The rendering look is authored in `main.tscn` plus a couple of shared pieces, all verified to work in the web `gl_compatibility` renderer (SSAO/DOF/volumetrics do **not** exist there — don't attempt them):
- **Key light** (`DirectionalLight3D`): warm `light_color (1, 0.94, 0.82)`, `light_energy 1.15`, rotated to ~35° elevation raking sideways across the +X run direction; `light_angular_distance = 1.5` makes the ProceduralSky draw a real sun disc. Shadows are tuned: `directional_shadow_mode = 1` (2 PSSM splits instead of the default 4), `directional_shadow_max_distance = 55`, `directional_shadow_blur = 1.2`, `shadow_normal_bias = 0.8` — crisper contact shadows *and* a 2–4× cheaper shadow pass than the old 100 m / 4 splits.
- **Sky** (`ProceduralSkyMaterial`): `sky_top_color (0.25, 0.45, 0.75)`, sky and ground horizon both `(0.85, 0.86, 0.80)` — the same value as `FOG_COLOR` (the fog-tracks-horizon contract) — desaturated-green ground bottom, `sun_curve 0.08` for a visible halo.
- **Glow + grade** (`Environment`): `glow_hdr_threshold = 0.85`, `glow_intensity = 0.6`, `glow_bloom = 0.05` — the glow pass was already always paid; now coins (emission raised to 1.6, `cast_shadow` off, permanent 15° rest tilt so the spin shows face and edge) genuinely cross the threshold and bloom. If glow ever blooms hot in the compatibility renderer (it hardcodes screen-blend), tune `glow_intensity` DOWN — don't raise the threshold. BCS grade: `adjustment_contrast 1.08`, `adjustment_saturation 1.18`, `tonemap_exposure 1.05`, `tonemap_white 1.2` (Filmic). **The `adjustment_*` BCS grade is desktop-only**: Godot's Compatibility renderer ignores `Environment.adjustment_*` entirely, so the web build renders without the contrast/saturation lift (harmlessly — the properties are skipped, not broken). That's consistent with the "desktop keeps full quality" convention (like MSAA 2 vs 0); don't try to reproduce the grade on web via a fullscreen shader.
- **`scripts/toon_shading.gd`** (`class_name ToonShading extends RefCounted`): one static `apply_to_mesh(mesh)` carrying the toon+rim material treatment (per-surface duplicate → `DIFFUSE_TOON`, rim 0.4 / rim_tint 0.25) plus a **static styled-material cache keyed by the source material's instance id** — the cache is the whole point: ~490 crocodiles sharing the same GLB materials get ONE styled duplicate per source material, never per-croc duplicates (which would be ~490 extra materials and break batching). `player_controller.apply_toon_shading` now just delegates to it; crocs apply it in their `_ready` mesh walk but get **no** inverted-hull outline overlay (a second draw call × 490 is unaffordable).

### Biomes (flat-world): desert / plains / forest / mountain + rivers
Walking ~1 km crosses visibly distinct regions. **The whole system is built *within* the flat-world invariant — do not break it.** The ground stays a flat `y = 0` plane (`terrain_height = 0.0`) because coin heights, coin-road placement, crocodile gravity settle, the player spawn at `(0, 2, 0)` and the per-chunk box ground collision all assume it. So **mountains are impassable block massifs you walk *around*, not raised terrain**, and **rivers are flat tinted wading bands** — a shader tint plus a speed penalty, with no water mesh, depth, transparency or reflection. Only the ground *shader* learns about biomes. The `ponytail:` upgrade path (recorded twice in `endless_terrain.gd`, in the `BIOME FIELD CONFIGURATION` constant banner and at the head of the `BIOME FIELD` function section): give the ground mesh vertex displacement plus a matching CPU height function, then make every y-placement site (`COIN_GROUND_HEIGHT`, croc spawn y, spawn point, block bases) ask it.

**One noise field decides everything.** `_biome_noise(world_x, world_z)` is a single octave of world-space value noise at `1.0 / BIOME_CELL_SIZE` (400 m ≈ 8 chunks), sampled at `world_xz / BIOME_CELL_SIZE + biome_offset` and clamped to 0..1. `biome_offset: Vector2` is how `run_seed` reaches the GPU (a shader can't take a 64-bit int): `_roll_biome_offset()` derives it from its own RNG seeded `hash(Vector3i(BIOME_SALT, 0, run_seed))` and is called from `_roll_run_seed()`, so `_ready()` and `new_run()` both get a fresh biome layout for free. Thresholding gives the four bands (`BIOME_DESERT_MAX` 0.34 / `BIOME_PLAINS_MAX` 0.62 / `BIOME_FOREST_MAX` 0.82 — plains most common, mountain rarest) and a thin **contour** of the same field gives rivers: `is_river_at(pos)` is `absf(noise - RIVER_LEVEL 0.5) < RIVER_HALF_WIDTH 0.007` (**tune by eye, not algebra** — the half-width was originally 0.02, derived from a guessed 0.005/m gradient; the field's measured mean gradient is ~0.0017/m, which made 6.7% of the world water with a 31 m median crossing. 0.007 gives a ~2.3% water share and an ~11 m median crossing along +X. Value noise has zero gradient at every lattice corner, so a corner hashing near 0.5 still yields the occasional lake — p95 crossing 61 m; rare enough to read as a landmark). `biome_at()` / `is_river_at()` are the **public API**; both are pure functions of world position + `biome_offset`, contain zero RNG draws, allocate nothing, and are safe to call every physics tick.

**CPU/GPU parity contract — `_biome_noise` in `endless_terrain.gd` and `biome_noise` in `assets/shaders/ground.gdshader` are the SAME function in two languages and must be edited together.** The blue band the player *sees* and the wading zone the player *feels* have to be the same band; rather than upload a texture or read back from the GPU, the GDScript port mirrors the GLSL exactly (`mod`↔`fposmod`, `fract`↔`v - floor(v)`, same `dot(p, p.yx + 33.33)` magic constants, same `f*f*(3-2f)` smoothstep weights), and the shader's `biome_noise` **reuses the existing `hash2`/`value_noise`** — that reuse is what keeps parity honest. `_apply_biome_shader_params()` pushes only the **parity-critical** uniforms (`biome_offset`, `biome_cell_size`, the three thresholds, `river_level`, `river_half_width`, `biome_blend`) onto the shared ground `ShaderMaterial`, guarded by an `is ShaderMaterial` check so the `@export var terrain_material` escape hatch still silently wins; it is called from `_ready()` after the default material is built and again from `new_run()` (after `_roll_run_seed()` in both). The **band colours are deliberately NOT pushed** — they live as shader defaults so an art pass can retint from the material without touching GDScript.

**Parity gotcha — `_biome_hash2` runs every step through `Vector2` on purpose, and that is not stylistic.** GDScript scalars are float64 while GLSL is fp32, and `Vector2` stores `real_t` = float32, so round-tripping through one is the only fp32 cast GDScript has. This matters because the hash **amplifies**: `v` reaches ~9.2e3 before the final `fract`, where an fp32 ULP is ~1e-3, so a last-bit difference upstream emerges ~200× larger. A float64 port therefore does not give "the same answer, more precisely" — it gives a *different field*. Measured against a strict-fp32 model of the GLSL, the naive version diverged by mean 3.1e-3 / max 1.0 with **8% of lattice corners past `RIVER_HALF_WIDTH` (0.007)**, i.e. ~20% of river area where the blue you see and the wading you feel disagreed — precisely the failure this contract exists to prevent. The current form matches the GLSL bit-for-bit over all 289×289 lattice corners. Don't "simplify" any line of it back to scalar arithmetic. `ponytail:` the residual risk is a driver contracting the `dot` into an FMA; the durable upgrade is hashing the wrapped *integer* lattice indices with `uint` bit ops (GLSL ES 3.00 has them, GDScript ints are exact), which removes float precision from the equation but changes the field, so `RIVER_HALF_WIDTH` would need re-tuning by eye.

**Shader side** (`ground.gdshader`, extended not replaced): the original two-green vertex noise stays as the PLAINS look and as base mottling under every biome. `vertex()` gains `v_biome` (raw noise) and `v_world_xz`; `fragment()` blends the plains albedo toward `desert_color`/`forest_color`/`mountain_color` with `smoothstep` over `BIOME_BLEND` at each threshold (soft boundaries; chunk seams were already free because the field is one continuous world-space function), then derives the river band factor `v_river` from the interpolated `v_biome`, `mix`es in `river_color` by it and pulls `ROUGHNESS` toward 0.3 for a wet sheen. **All the noise stays per-VERTEX**; the two per-fragment additions are the river band factor (a subtract, an abs and a `smoothstep` — no noise) and, guarded behind `if (v_river > 0.0)` so the ~95% of pixels outside a river pay nothing, the shimmer. **The band factor must NOT be a varying:** the band is ~8 m wide and its soft edge spans under 2 m, while the ground plane's vertex spacing is ~3 m (16×16 over a 50 m chunk), so interpolating it undersamples the one nonlinear quantity in the shader and the blue you *see* parts company with the wading zone you *feel* by a metre or two — exactly what the CPU/GPU parity contract exists to prevent. `v_biome` itself is safe to interpolate (a 400 m wavelength is near-linear over 3 m).

**Determinism: independent stream + post-draw skips.** New geometry uses its own stream — `spawn_biome_content_in_chunk` seeds `hash(Vector3i(cx * 83492791, cy * 15485863, run_seed ^ BIOME_SALT))`, deliberately *different* multiplier primes from the artifact/object streams (73856093 / 19349663) so the sequences can't correlate. Every place a biome *removes* an existing placement is a `continue` **after** the RNG draws that produced the candidate — the draws still advance the stream. Sites: `spawn_objects_in_chunk` (river skip, plus the desert thinning below), the four `spawn_feature_structure` builders (one centre test each — a centre check is deliberately enough; no footprint-vs-band intersection), `spawn_crocodiles_in_chunk` (river skip with `chunk_croc_target` **untouched** — the retry budget absorbs it), and `_artifact_at` (the river test is folded into the *existing* candidate-acceptance condition, so the 2-draws-per-try shape is unchanged). **One exception to "the world outside rivers is byte-identical to before biomes existed", worth knowing when auditing determinism:** a feature structure rejected for standing in a river `return`s *before* its own `create_box` loop, and `spawn_feature_structure` runs off the **shared chunk RNG** ahead of the scattered-block loop — so those 10–60 skipped draws reshuffle that one chunk's scattered blocks, including blocks nowhere near the water. Hoisting the draws to keep them would be a large change for a property with no gameplay value; what is load-bearing is determinism **within** a run, and that holds unconditionally because `is_river_at` is a pure function. **Coins and bosses are deliberately not excluded**: road coins in a river stay (wading for coins is the intended micro-decision) and bosses own road stations, which are the one thing that crosses a river.

**What each biome builds** (`spawn_biome_content_in_chunk`, gated by `@export var spawn_biome_content`, wired into `create_chunk` **after `spawn_artifact_in_chunk` and before `_build_block_multimesh`** — same ordering contract as artifacts, so the geometry joins the chunk's single MultiMesh + single `BlockCollision` body and its footprints land in `obstacles` before crocodiles and coins read them). The chunk **centre** picks which builder runs; individual builders re-test `biome_at` at each candidate's own position so biome edges feather across chunk seams instead of stopping dead at one.
- **DESERT** — sparse, not empty. The emptiness comes from `spawn_objects_in_chunk` dividing its scattered-block **target** by `DESERT_BLOCK_KEEP_EVERY` (3) — a **target, not a roll**, so no draw is inserted anywhere (measured: 4 scattered blocks per desert chunk vs 12 on plains). An earlier version keyed the skip off the loop's `attempts % 3` counter instead; that was silently a no-op, because `max_attempts` is `objects_per_chunk * 3`, so exactly `objects_per_chunk` attempts stayed eligible and the quota still filled (~84% kept). The builder then adds 4–9 cactus stacks (2–3 thin green boxes, sometimes one arm), kept `CACTUS_ROAD_CLEARANCE` 12 m off the road — cactus footprints are non-climbable, so one standing on the coin swath makes `_settle_coin_y` **skip** road coins rather than perch them, punching holes in the trail. **Croc density is unchanged** — a desert reads empty through decoration only, per the "entity counts are never reduced" rule.
- **FOREST** — 25–40 trees, each one solid trunk box + 2–3 shrinking canopy slabs passed `collide = false`. All of it rides the chunk's one MultiMesh, so **a forest chunk is the same single block draw call as a plains chunk**; only trunks pay a `CollisionShape3D`. Each trunk appends a **non-climbable** footprint stopping at *trunk* height — non-climbable on purpose, so `_settle_coin_y` **skips** a road coin over a tree instead of perching it 5 m up in the canopy where nobody can reach it.
- **MOUNTAIN** — 2–4 massifs, each a stack of tapering boxes (8–20 m tall) with per-layer yaw and lateral jitter so it doesn't read as a wedding cake, grey scree colours from a small ramp, and the top 1–2 layers forced snow-white above `MOUNTAIN_SNOW_HEIGHT`. The layer count is **not rolled** — it is `maxi(2, int(height / MOUNTAIN_MIN_LAYER_HEIGHT))` (4 m), so 2–5 layers. That is what makes "impassable, walk around it" true: at 8 m over 7 layers a massif would be a 1.14 m staircase with a 1.7 m ledge per level, i.e. a walkable ziggurat, and the player's jump apex is 3.61 m. (An earlier version drew a 4–7 count and clamped it with the same expression; the clamp always won, so the draw was dead and the "4–7 layers" never happened.) Bases keep `MOUNTAIN_EDGE_MARGIN` (10 m, covering the rotated `MOUNTAIN_BASE_WIDTH_MAX * 0.71 + MOUNTAIN_LAYER_JITTER` = 9.73 m reach — layers are yawed, so the half-*diagonal* is the bound, not the half-width) from the chunk edge so a massif never straddles a seam, while still leaving a 30×30 m placement box so peaks spread out instead of piling into every chunk's centre. Massifs are overlap-tested against **other massifs plus any obstacle already in the chunk with `radius >= MOUNTAIN_AVOID_RADIUS` (2 m)** — a local `avoid` list, not the chunk's full `obstacles`: a massif footprint radius is ~9.7 m, so demanding clearance from all dozen scattered blocks (radius ≤ 1.78 m) would cover the whole chunk and mountains would stop generating, and a block swallowed by rock is invisible anyway — but an artifact (radius ≥ 2.5 m) swallowed by rock takes its coin ring and its one guaranteed gem with it. One non-climbable footprint each with the real top height.

**`_biome_spot_ok(chunk_center, local_x, local_z, radius, road_clearance, obstacles)`** is the single home of the "would something solid here spoil what is already there?" rule: true when the spot is **not** in a river, is at least `road_clearance` from the coin-road centerline (`_road_lateral_distance`), and its `radius` overlaps nothing in `obstacles`. Callers pass different clearances — `CACTUS_ROAD_CLEARANCE` 12 m, `FOREST_ROAD_CLEARANCE` 14 m (≥ half of `road_width_max` 20, so the scattered coin swath stays tree-free) and `MOUNTAIN_ROAD_CLEARANCE` 24 m, which buys **a canyon through the range for free**. `radius` is always the **widest the thing could be**, because the real width is drawn *after* this call and reordering the draws to know it exactly would shift the biome stream for nothing. Its river test is **inert as the constants stand** (`RIVER_LEVEL` 0.5 falls inside the plains band, and these three callers only build in desert/forest/mountain) — kept as the thing that stays correct if `RIVER_LEVEL` or the thresholds are retuned; the river exclusions that actually fire are the plains-capable ones listed above. There is no upper bound on the clearance: `_road_lateral_distance(world_x, world_z, clearance)` sizes its station scan window from the clearance it is handed (it used to hardcode `ARTIFACT_ROAD_CLEARANCE` 14, which left `MOUNTAIN_ROAD_CLEARANCE` 24 just under the honest-answer bound).

**Player + audio side.** `player_controller.gd` gained exactly one behaviour: `_terrain_is_river_here()` (group `"terrain"` + `has_method("is_river_at")` guard, modelled on `_weather_is_raining_here()`, returns false when absent so the player scene still runs standalone) sets `var is_wading` once per physics tick, and only while `is_on_floor()` — flying over a river is not wading. `WADE_SPEED_FACTOR` (0.6) multiplies into the **grounded gaits only** in `calculate_current_speed()`; Windman's `WINDMAN_AIR_SPEED` early-return is untouched. **The run gait is floored at `WADE_RUN_MIN_SPEED` (9.0)** — the difficulty contract is "running always escapes", which is why `MAX_CHASE_SPEED` (8.5) sits under the slowest character's run (10.0 × 0.9 = 9.0); the raw wade factor would drop that run to 5.4, below even `BASE_CHASE_SPEED` 5.5, turning a river into an unescapable trap (crossings are not length-bounded — see the `RIVER_HALF_WIDTH` note). Walk and duck take the full drag, so a river is still a real decision. The flag needs **no reset plumbing** — it is recomputed from scratch every tick and holds no history. At the existing footstep hook in `update_character_animation`, a one-line ternary fires `"play_splash"` instead of `"play_footstep"`, so the splash cadence comes free from the walk sine's zero crossings (no new timer). `sound_manager.play_splash()` **replays the existing footstep buffer** at `SPLASH_PITCH` 1.9 and ~5 dB louder — a brighter, wetter slap — through `_play_oneshot`, so it inherits the `_unlocked` gesture gate and bakes no new stream (the "no audio asset files" invariant holds).

## Performance & web build
The game ships primarily as a **web (WebGL) build**, which is the performance-sensitive target. Several systems exist purely to keep it smooth in a browser without changing how it looks or plays on desktop:

- **Debug perf overlay** (`scripts/perf_overlay.gd`): a `Label` named `PerfOverlay` under the `HUD` `CanvasLayer` in `main.tscn`. Shows FPS, process ms, physics ms, draw calls (`RENDER_TOTAL_DRAW_CALLS_IN_FRAME`), primitives, total node count, and `Crocs (active/total)`. **Toggle with F3.** It starts visible only in `OS.is_debug_build()` and stays hidden in release until F3 is pressed, so it never ships in the player's face. This is the measurement tool — use it to prove perf changes and catch regressions.
- **Simulation LOD** for crocodiles — see the "Crocodile simulation LOD" section above.
- **MultiMesh block rendering + consolidated per-chunk collision** — see "Everything in the world is spawned procedurally" above.
- **Web-only render/GPU tuning** in `project.godot` `[rendering]` via Godot's `.web` per-platform override suffix (the un-suffixed key is the desktop/editor default, the `.web` key only applies in the HTML5 export): `renderer/rendering_method.web = "gl_compatibility"` (the lightweight WebGL2 path; desktop keeps `Forward Plus` from `config/features`), `anti_aliasing/quality/msaa_3d.web = 0` (desktop keeps `msaa_3d = 2`), `lights_and_shadows/directional_shadow/size.web = 1024` (shadows stay **on**, just smaller), and `scaling_3d/mode = 0` + `scaling_3d/scale.web = 0.8` (renders web at 80% then upscales; desktop scale stays 1.0 and `mode = 0`/Bilinear is inert there).
- **Runtime tuning** in `endless_terrain.gd`: `_ready()` lowers `render_distance` to `WEB_RENDER_DISTANCE = 3` on web only (49 active chunks vs 121 on desktop, gated behind `OS.has_feature("web")`), and `_setup_fog()` enables exponential depth fog **on every platform** — the sanctioned exception to the web-gate rule, see "Performance conventions" below. `fog_light_color = FOG_COLOR = Color(0.85, 0.86, 0.80)`, which **must equal** `sky_horizon_color` and `ground_horizon_color` in `main.tscn` (the fog-tracks-horizon contract: if the sky changes, all three move together, so the view edge dissolves into the sky); `fog_sun_scatter = 0.15` adds a gentle bright streak toward the warm sun. Only the **density** stays platform-gated: `FOG_DENSITY_WEB = 0.005` (thick — masks the short web view distance) vs `FOG_DENSITY_DESKTOP = 0.0022` (thin depth haze over the long desktop view). The fog is built on a runtime `duplicate()` of the `WorldEnvironment.environment` so the shared inline SubResource is never mutated.

### Performance conventions (important)
When optimizing, follow the split this work established:
- **Visual-affecting changes are web-gated.** Anything a player could see (renderer, MSAA, shadow size, internal resolution, render distance) must be limited to the web build via `OS.has_feature("web")` at runtime or a `.web` project-setting override. Desktop/editor stay at full quality. **One sanctioned exception: fog is universal** — an owner-approved art-direction call (desktop gets the thin 0.0022 haze so the horizon dissolves instead of hard-edging). The fog *density* is still platform-gated, so the perf/view-distance side of fog remains a web concern; don't use the fog exception as precedent for other visual changes.
- **Purely invisible optimizations are global.** MultiMesh batching, crocodile simulation LOD, and consolidated collision change neither look nor gameplay anywhere, so they run on every platform (and benefit desktop too).
- **Entity counts are never reduced as an optimization.** Same blocks per chunk as before; croc count per chunk changes only by *design* (the distance-scaled density in the difficulty gradient), never for perf. (Coins are an exception only because their placement changed by *design*, not for perf: they are now road-shaped rather than uniform per-chunk scatter, so off-road chunks legitimately have no coins — see "coin road" above.) Distant crocodiles are **slept** (frozen, monitoring off), never removed — counts stay unchanged and gameplay near the player is identical.

## CI/CD
`.github/workflows/build.yml` builds the web export on every push. Deploy to GitHub Pages happens **only on push to `master`**; `claude/*` branches build (and upload a downloadable `web-build` artifact) but do not deploy. So merging to `master` is what publishes the playable build.

## Conventions
- GDScript with explicit type hints throughout; constants for tunable values (`WALK_SPEED`, `DETECTION_RADIUS`, etc.) declared at the top of each script.
- Gravity is per-script and intentionally non-physical: the player uses `gravity = 14.4` with `JUMP_VELOCITY = 10.2` — an arcade-snappy arc whose apex (`v²/2g = 3.6125 m`) is byte-identical to the old floaty 5.1 / 3.6 tuning, so 2.5 m blocks stay jumpable while airtime halves (~1.42 s); Windman's glide gravity is likewise preserved exactly (`14.4 × WINDMAN_GRAVITY_FACTOR 0.1125 = 1.62`, the old `3.6 × 0.45`). Jumps get `COYOTE_TIME` / `JUMP_BUFFER_TIME` (0.12 s each) forgiveness, and horizontal velocity approaches its target via `move_toward` at `MOVE_ACCELERATION` (40 m/s²) instead of snapping. Crocodiles use `GRAVITY = 9.8`.
- Input actions are defined in `project.godot` (`move_forward`/`move_backward`, `turn_left`/`turn_right`, `step_left`/`step_right`, `jump`, `run`, `duck`, `switch_character`, `special_ability`, `toggle_camera`) — reference these action names, don't hardcode keycodes.
