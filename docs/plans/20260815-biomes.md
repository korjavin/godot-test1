# Biomes: deserts, forests, rivers, mountains over the flat-world invariant

## Overview

The world is visually homogeneous: every chunk is the same green plane with the same
earthy blocks. This plan adds **biomes** that appear randomly across the map — desert,
forest, plains (the current look), mountain fringe — plus **rivers** as winding blue
wading bands.

**THE CORE CONSTRAINT — do not violate it.** The whole game assumes **FLAT walkable
ground at y = 0** (`terrain_height = 0.0`): coin heights, the coin-road placement, crocodile
gravity settle, the player spawn at `(0, 2, 0)`, and the per-chunk box ground collision all
depend on it. **Do NOT introduce a heightfield / displaced ground mesh.** Everything here is
built *within* the flat-world invariant:

- **Mountains** are impassable **block-built massifs** (stacked boxes through the existing
  MultiMesh + consolidated collision), not raised terrain. You walk *around* them.
- **Rivers** are **flat tinted wading bands** — a shader tint on the flat ground plus a
  speed penalty. No water mesh, no depth, no transparency, no reflection.
- The ground plane stays exactly as it is; only its **shader** learns about biomes.

Mark this decision in the code with a `ponytail:` comment naming the heightfield as the
upgrade path (see Task 1).

**Benefits:** walking ~1 km crosses visibly distinct regions with soft colour transitions;
rivers give a small readable movement decision; forests and mountains break up the sightline
without costing draw calls (all geometry joins the per-chunk block MultiMesh).

### House rules this codebase enforces (violating these fails review)

1. **Teaching-style comments.** Every script is written to be *read*. New functions get a
   docstring (`"""..."""`) with `@param` / `@return` lines and an EDUCATIONAL NOTE where a
   non-obvious technique is used. Match the surrounding comment density — it is high.
2. **Explicit type hints everywhere** (`func f(x: float) -> Vector3:`, `var n: float := ...`
   style used in the file — follow the exact local convention: `var x := 1.0` inferred where
   the RHS is unambiguous, explicit `: Type` on params/returns/exports always).
3. **Constants at the top of the script**, grouped under a banner comment, with a short note
   on what each tunes.
4. **HARD determinism.**
   - Within a run, a revisited chunk must regenerate **byte-identically**. Chunk generation
     order must never change content (chunks build time-sliced, in arbitrary order).
   - Two different runs must differ (mix `run_seed` into every hash).
   - **Never insert or remove a draw from an existing RNG stream.** Biome decisions that
     affect existing spawners must be implemented as **`continue`/skip AFTER the draws have
     happened** (the draws still advance the RNG; only the placement is skipped), or must use
     an **independent hash stream** like `_artifact_at`/`_boss_at`.
5. **Per-chunk parenting.** Anything spawned per chunk parents to the chunk `MeshInstance3D`
   so it frees when the chunk unloads.
6. **Keep everything batched.** All new solid geometry goes through `create_box` into the
   chunk's existing `block_batch` (one MultiMesh) and `block_body` (one StaticBody3D).
   **F3 draw calls must stay in the same ballpark** despite forests and mountains.
7. **Entity counts are never reduced as an optimization** (croc density per chunk is
   UNCHANGED by biome — deserts feel empty via *decoration*, not fewer entities). The one
   sanctioned exclusion is the river band, which is a design rule, not an optimization.

## Implementation Steps

### Task 1: Biome field — deterministic noise, biome classification, river test

All of this lands in `scripts/endless_terrain.gd` in a new clearly-bannered
`BIOME FIELD` section (constants at the top of the file with the other constant banners;
functions in a new section near the coin-road math section).

- [x] Add the constants block near the other `@export`/`const` banners at the top:
  - `BIOME_SALT: int` — an arbitrary fixed salt for the independent hash stream (pick a hex
    constant in the style of `ARTIFACT_SALT` / `BOSS_SEED`).
  - `BIOME_CELL_SIZE: float = 400.0` — noise wavelength in metres. Chunks are 50 m, so a
    biome cell spans ~8 chunks (the bead asks for 6–10). One octave of value noise at this
    wavelength is the whole field.
  - `BIOME_DESERT_MAX: float`, `BIOME_PLAINS_MAX: float`, `BIOME_FOREST_MAX: float` —
    the noise thresholds separating the four bands (suggested `0.34 / 0.62 / 0.82`, so
    plains is the most common, mountain the rarest).
  - `RIVER_LEVEL: float = 0.5` and `RIVER_HALF_WIDTH: float = 0.02` — the contour trick.
  - `BIOME_BLEND: float` — noise-space half-width of the soft colour transition used by the
    shader (used as a `smoothstep` radius, e.g. `0.05`).
- [x] Add an enum for readability: `enum Biome { PLAINS, DESERT, FOREST, MOUNTAIN }`
      (a bare `enum` at the top of the script; **note**: `Biome.RIVER` is deliberately NOT a
      member — river is an *overlay* on whatever biome the ground is, tested separately).
- [x] Add `var biome_offset: Vector2` — a per-run domain offset derived from `run_seed` (this
      is how the run seed reaches the shader, which cannot take a 64-bit int). Compute it in
      a small `_roll_biome_offset()` helper from a `RandomNumberGenerator` seeded
      `hash(Vector3i(BIOME_SALT, 0, run_seed))` (its own stream — touches nothing else),
      producing two floats in a large range (e.g. `randf_range(-4096.0, 4096.0)` each).
      Call it from `_roll_run_seed()` so `_ready()` and `new_run()` both get it for free.
- [x] Implement the noise, **mirroring `assets/shaders/ground.gdshader` exactly** (same
      `mod(p, 289.0)` wrap, same magic constants, same smoothstep weights) so the GDScript
      answer and the GPU answer agree:
  - `_biome_hash2(p: Vector2) -> float` — the GLSL `hash2` port.
  - `_biome_value_noise(p: Vector2) -> float` — the GLSL `value_noise` port.
  - `_biome_noise(world_x: float, world_z: float) -> float` — one octave at
    `1.0 / BIOME_CELL_SIZE`, sampled at `(world_xz / BIOME_CELL_SIZE) + biome_offset`,
    clamped to 0..1. **This is the single field everything reads.**
  - Docstring must state the **shader-parity contract**: this function and the GLSL copy
    must be edited together, and a `ponytail:` note that GDScript floats are doubles while
    GLSL is fp32, so the river band edge can differ by a fraction of a metre between the
    blue tint and the wading zone — harmless, and cheaper than uploading a texture.
- [x] `func biome_at(world_x: float, world_z: float) -> Biome` — threshold the noise into
      the four bands. Pure function, no RNG.
- [x] `func is_river_at(world_pos: Vector3) -> bool` — the contour trick:
      `absf(_biome_noise(world_pos.x, world_pos.z) - RIVER_LEVEL) < RIVER_HALF_WIDTH`.
      **This is the public gameplay API** the player polls (Task 7). One noise eval, no
      allocation, safe to call every physics tick.
- [x] Add the **flat-world `ponytail:` comment** at the top of the new section, in this
      spirit: *"ponytail: the ground stays a flat y=0 plane. Mountains are block massifs you
      walk around and rivers are flat tinted wading bands, because a real heightfield would
      break coin heights, road placement, croc gravity settle, spawn and the per-chunk box
      ground collision all at once. Upgrade path if a real heightfield is ever wanted: give
      the ground mesh vertex displacement + a matching CPU height function, then make every
      y-placement site (COIN_GROUND_HEIGHT, croc spawn y, spawn point, block bases) ask it."*

### Task 2: Ground shader — biome tint + river band with shimmer

Extend `assets/shaders/ground.gdshader`. **Do not replace the existing two-green vertex
noise** — that stays as the PLAINS look and as the base mottling under every biome.

- [x] Add uniforms, all with `source_color` on the colours and sensible defaults so the
      shader still looks right if nothing sets them:
  - `biome_offset: vec2` (default `vec2(0.0)`) — the per-run domain offset from Task 1.
  - `biome_cell_size: float` (default `400.0`) — **must equal** `BIOME_CELL_SIZE`.
  - `river_level`, `river_half_width`, `biome_blend`, and the three band thresholds — as
    floats mirroring the GDScript constants.
  - `desert_color` (ochre/sand, e.g. `vec3(0.78, 0.68, 0.44)`), `forest_color` (deep cool
    green, e.g. `vec3(0.13, 0.30, 0.17)`), `mountain_color` (grey-brown scree, e.g.
    `vec3(0.45, 0.43, 0.40)`), `river_color` (dark blue-teal, e.g. `vec3(0.10, 0.28, 0.34)`).
- [x] Add `float biome_noise(vec2 world_xz)` reusing the **existing** `hash2` / `value_noise`
      functions (that reuse is the whole point — it is what keeps CPU/GPU parity honest).
- [x] In `vertex()`: compute the biome noise at the vertex's world XZ (the existing
      `world_xz` local is already there) and pass **two** new varyings:
      `v_biome` (the raw noise) and `v_river` (a `smoothstep`-softened 0..1 river factor,
      1 in the band centre falling to 0 at the band edge — a hard step would alias badly at
      16×16 vertex density, so soften it over a fraction of `river_half_width`).
      Also pass `v_world_xz` for the shimmer.
      ⚠️ DEVIATION: `v_river` is **not** a varying — it is computed per-FRAGMENT from the
      interpolated `v_biome`. The band is ~8 m wide with a soft edge under 2 m, while the
      ground plane's vertex spacing is ~3 m, so interpolating the band factor undersamples
      the one nonlinear quantity in the shader and the blue you see parts company with the
      wading zone you feel — the exact mismatch the parity contract exists to prevent.
      `v_biome` (400 m wavelength) is safe to interpolate; the cost is a subtract, an abs
      and a smoothstep, no noise. The soft edge is also **centred on** `river_half_width`
      rather than fading inward to it, so the fully-tinted region and the wading region
      agree at the boundary instead of the tint dying half a metre inside the water.
- [x] In `fragment()`: keep the existing `mix(green_a, green_b, v_noise)` as the plains
      albedo, then blend toward the biome colours with `smoothstep` over `biome_blend` around
      each threshold — so transitions are **soft and cross chunk seams invisibly** (the noise
      is one continuous world-space field, so seams are already free; the softness is about
      the *biome boundary*, not the chunk boundary).
- [x] River on top: `ALBEDO = mix(biome_albedo, river_albedo, v_river)` and pull `ROUGHNESS`
      down toward ~0.3 by the same factor (a wet sheen for free — no transparency, no
      reflection, no extra pass).
- [x] Shimmer, **guarded so the 95%-of-pixels non-river case pays nothing**: inside
      `if (v_river > 0.0)`, modulate the river albedo with a cheap couple of
      `sin(v_world_xz.x * a + TIME * b) * sin(v_world_xz.y * c - TIME * d)` terms at a small
      amplitude. Keep it to a handful of ALU ops — this is a mobile/WebGL2 fill-rate budget.
- [x] Extend the shader's header comment block: the existing PERFORMANCE CONTRACT and
      SEAMLESSNESS CONTRACT sections must be updated to cover the biome/river additions
      (in particular: biome noise is per-VERTEX like everything else; only the guarded
      shimmer is per-fragment, and only inside rivers).

## Technical Details

**Biome field.** One octave of world-space value noise, wavelength `BIOME_CELL_SIZE` (400 m
≈ 8 chunks), domain-offset per run by `biome_offset` (derived from `run_seed`). Thresholding
its 0..1 output gives four bands; the contour `|n - RIVER_LEVEL| < RIVER_HALF_WIDTH` gives
rivers. Band width in metres ≈ `RIVER_HALF_WIDTH / |∇n|`; with a 400 m wavelength the
gradient is roughly `0.005 /m`, so `0.02` yields a river ~8 m wide. **Tune
`RIVER_HALF_WIDTH` by eye, not by algebra** — the estimate is only a starting point.

**Why the same noise twice (GDScript + GLSL).** The blue band the player *sees* and the
wading zone the player *feels* must be the same band. Rather than upload a texture or read
back from the GPU, the tiny noise function exists in both languages with identical constants.
The fp64-vs-fp32 mismatch shifts the band edge by centimetres — mark it `ponytail:` and move
on.

**Determinism recap (the thing most likely to be got wrong).**
- New content → new independent stream: `hash(Vector3i(cx * p1, cy * p2, run_seed ^ BIOME_SALT))`.
- Existing content → biome only ever *removes* a placement, and only *after* the RNG draws
  that produced it. Never reorder, never add a draw, never skip a draw.
- `biome_at` / `is_river_at` are pure functions of world position + `biome_offset`, so a
  chunk regenerates identically no matter when it is built.

**Draw-call budget.** Trees, cacti and massifs are `create_box` entries → they land in the
chunk's single `MultiMeshInstance3D`. A forest chunk must still be **one** block draw call.
The only per-fragment addition anywhere is the river shimmer, guarded behind `v_river > 0.0`.
